# 1. 비즈니스/서비스 소개

## 1-1. 한 문장 정의

> **Thinking Flow는 AI 시대에 "AI가 대신 생각해주지 않는" 유일한 학습 서비스입니다.
> 사용자가 자기 생각을 먼저 꺼내고, 10단계 논리적 사고 절차를 반복 훈련하며,
> 그 사고 과정과 수정 이력을 데이터로 남겨 포트폴리오로 전환합니다.**

## 1-2. 엘리베이터 피치 (30초)

ChatGPT에 물어보면 30초 만에 그럴듯한 기획안이 나옵니다.
그런데 면접에서 "왜 그렇게 판단하셨어요?"라는 질문을 받으면 답을 못 합니다.
**결과물은 남았는데, 생각한 과정은 남지 않았기 때문입니다.**

Thinking Flow는 순서를 뒤집습니다.
AI가 먼저 답을 주지 않습니다. **사용자가 먼저 씁니다.**
그다음에야 AI가 "여기 근거가 빠졌어요", "이건 사실인가요, 해석인가요?"라고 되묻습니다.

목적·맥락 이해부터 결론·회고까지 10단계를 밟고 나면,
결과물뿐 아니라 **처음 생각 → 왜 바꿨는지 → 최종 판단까지의 전 과정**이 데이터로 남습니다.
그리고 그 기록은 그대로 포트폴리오, 기술 블로그, 면접 답변으로 변환됩니다.

## 1-3. 무엇을 파는가

| 구분 | 내용 |
| --- | --- |
| **표면적 제품** | 10단계 사고 훈련 워크스페이스 + AI 점검 코치 |
| **실제 파는 것** | ① 반복 가능한 사고 절차의 **내재화** ② 조작 불가능한 **사고 과정의 증거** |
| **핵심 객체** | **Thinking Case** — 하나의 문제에 대한 관찰·정의·구조화·가설·검증·판단·실행·회고의 전체 기록 |
| **결과물** | Case Summary(내부 검토용) → Portfolio / 기술 블로그 / 면접 답변(외부 설명용) |

## 1-4. 세 개의 시스템

```
Thinking Learning System   →   10단계를 반복 훈련한다
        ↓
Thinking Data System       →   초안·수정·근거·판단·회고를 시간순으로 보존한다
        ↓
Thinking Portfolio System  →   원본과 연결된 결과물로 전환한다
```

이 세 시스템이 **하나의 흐름으로 연결되어 있다는 것**이 구조적 차별점입니다.
사고 훈련 도구는 있고, 노트 앱도 있고, 포트폴리오 서비스도 있습니다.
그러나 **훈련한 내용이 그대로 증거가 되고, 그 증거가 그대로 포트폴리오가 되는** 연결은 없습니다.

---

## 1-5. USP — 왜 이것이어야 하는가

### ① AI가 답을 먼저 주지 않는다 (선작성 · 후개입)

대부분의 AI 서비스는 "얼마나 빨리 좋은 답을 주는가"로 경쟁합니다.
Thinking Flow는 **답을 주지 않는 것**을 기능으로 삼습니다.

- 사용자가 작성하기 전에는 AI Coach가 `locked` 상태다
- AI는 완성 답안을 만들지 않는다
- AI는 누락·혼재·논리적 공백·반례와 추가 질문만 제공한다
- AI는 단계 완료나 최종 대안을 **대신 결정하지 않는다**

> 이것은 기술적으로 어려운 기능이 아니라 **지키기 어려운 원칙**입니다.
> 그래서 모방이 쉽지 않습니다. 경쟁사가 이 원칙을 따라 하려면 자사 제품의 핵심 소구점을 버려야 합니다.

### ② 틀린 생각이 지워지지 않는다 (append-only 버전 이력)

일반 문서 도구는 수정하면 이전 내용이 사라집니다.
Thinking Flow는 **덮어쓰지 않고 버전으로 쌓습니다.**

- 최초 자유 작성 · 구조화 입력 · 수정 전후 버전을 모두 보존
- AI 피드백을 **채택한 기록뿐 아니라 거절한 기록도** 사용자의 판단 데이터로 저장
- 자유 작성 ↔ 구조화 입력을 전환해도 양쪽 내용이 모두 남음

> "처음엔 A라고 생각했는데 B라는 근거를 보고 C로 바꿨다" —
> 이 문장을 **증거와 함께** 말할 수 있는 사람은 거의 없습니다. 그것이 이 제품이 만드는 자산입니다.

### ③ 포트폴리오가 원본으로 역추적된다 (조작 불가능한 증거)

- 모든 파생 섹션은 원본 Stage · FieldResponse · ResponseVersion으로 되돌아갈 수 있다
- 원본에 없는 성과·역할·수치·인과를 **생성하지 않는다**
- "계획"과 "가상 검증"과 "실제 실행 결과"를 구분해 표시한다
- 원본이 바뀌면 파생 결과물에 stale 상태를 표시한다

> AI로 포트폴리오를 그럴듯하게 쓰는 것은 이제 누구나 합니다. 그래서 아무도 안 믿습니다.
> **역추적 가능성**이 신뢰의 새로운 기준이 됩니다.

### ④ 성장이 감이 아니라 데이터로 보인다

- 단계별 소요 시간 변화, AI 점검 없이 완료한 단계 수, 반복 취약점 감소
- 모든 지표는 **계산식과 원본 기록으로 설명 가능**해야 함
- 근거 없는 역량 점수와 **사용자 간 순위는 만들지 않음**

### ⑤ 반복할수록 도움을 줄인다

목표는 사용자를 오래 붙잡아두는 것이 아니라, **가이드 없이도 같은 사고 흐름을 수행하게 만드는 것**입니다.
이것은 리텐션에 불리해 보이지만, 학습 서비스에서는 가장 강한 신뢰 자산이자 추천 동기가 됩니다.

## 1-6. 경쟁 대비 위치

| 대안 | 사용자가 얻는 것 | 못 얻는 것 |
| --- | --- | --- |
| ChatGPT / Claude 등 범용 AI | 빠른 결과물 | 자기 사고 절차, 과정 기록, 성장 증거 |
| Notion 등 문서 도구 | 자유로운 기록 | 사고 절차 가이드, 단계별 점검, 버전의 의미 |
| 사고법 강의·도서 (MECE, 5Why, SCQA) | 개념 이해 | 실제 문제 적용, 피드백, 반복 훈련 |
| 포트폴리오 플랫폼 | 결과물 전시 | 판단 과정의 증거, 역추적 가능성 |
| 취업 컨설팅 | 개인화 피드백 | 반복 가능성, 비용 효율, 데이터 축적 |

**Thinking Flow의 자리** — 위 다섯 가지가 각각 채우지 못한 틈, 즉
**"절차 학습 + 과정 기록 + 증거 기반 포트폴리오"가 하나로 연결된 지점**입니다.

## 1-7. 하지 않는 것 (비목표)

USP는 무엇을 하지 않는지로도 정의됩니다.

- 한 번의 요청으로 완성 답안을 생성하지 않는다
- AI가 모든 단계를 자동 완성하지 않는다
- 검증되지 않은 기업 내부 데이터나 성과를 사실처럼 제시하지 않는다
- 포트폴리오 문장을 원본과 분리된 최종 텍스트로만 저장하지 않는다
- 사용자 간 순위나 근거 없는 역량 점수를 만들지 않는다

# 2. 주요 고객 (Target)

## 2-1. 1차 타겟 (대표 사용자)

> **AI를 자주 활용하지만, 자신의 논리적 사고력과 문제 해결력을 스스로 키워
> 프로젝트와 포트폴리오로 증명하고 싶은 취업준비생 · 직무 전환자**

### 왜 이들인가 — 세 가지 조건이 동시에 성립하는 유일한 집단

| 조건 | 설명 |
| --- | --- |
| **① 문제를 이미 느끼고 있다** | AI로 결과물은 만들지만 "이게 내 실력인가?"라는 불안이 실재한다 |
| **② 증명해야 할 마감이 있다** | 서류·포트폴리오·면접이라는 **날짜가 정해진 강한 동기**가 있다 |
| **③ 시간을 투자할 의향이 있다** | 10단계라는 긴 절차를 감수할 만한 절박함과 가용 시간이 있다 |

> 특히 ②가 결정적입니다. Thinking Flow는 마찰이 큰 제품이므로,
> **"당장 필요한 이유"가 없는 사용자는 완주하지 않습니다.**

## 2-2. 페르소나

### 페르소나 A — "결과는 있는데 과정을 설명 못 하는" 취준생

| 항목 | 내용 |
| --- | --- |
| **상황** | 데이터 분석/PM/서비스 기획 직무 준비. 포트폴리오에 프로젝트 3개 보유 |
| **행동** | 문제 정의부터 결론까지 대부분 AI와 대화하며 진행. 산출물 품질은 나쁘지 않음 |
| **결정적 순간** | 면접에서 "이 지표를 왜 골랐나요?", "다른 대안은 검토 안 하셨어요?" → 답이 막힘 |
| **진짜 니즈** | 결과물 개선이 아니라 **판단 근거를 말할 수 있는 상태** |
| **Thinking Flow에서 얻는 것** | 대안 비교·기준·불확실성이 기록으로 남아, 면접 답변으로 그대로 변환 |

### 페르소나 B — "빈 화면 앞에서 멈추는" 직무 전환자

| 항목 | 내용 |
| --- | --- |
| **상황** | 비기획 직군 → 기획/분석 직군 전환 준비. 실무 문제를 다뤄본 경험이 적음 |
| **행동** | 사고법 강의는 들었지만 실제 문제에 MECE·5Why를 적용하지 못함 |
| **결정적 순간** | 빈 문서를 열고 첫 문장을 못 씀 → 결국 AI에게 초안을 시킴 |
| **진짜 니즈** | 정답이 아니라 **시작할 수 있는 절차와 안전한 연습 문제** |
| **Thinking Flow에서 얻는 것** | Practice Case의 맥락 + 단계별 질문으로 빈 화면 공포 해소, 반복으로 절차 내재화 |

### 페르소나 C — "AI 의존이 불안한" 실무 초년생 (확장 후보)

| 항목 | 내용 |
| --- | --- |
| **상황** | 입사 1~3년차. 업무에 AI를 적극 활용 중 |
| **행동** | 산출물은 빨라졌으나 상사의 "왜?"에 즉답하지 못하는 경험이 누적 |
| **진짜 니즈** | 실무 문제를 자기 절차로 처리하는 훈련 + 이직 대비 사고 포트폴리오 |
| **주의** | 마감 동기가 취준생보다 약함 → 완주율이 낮을 수 있음. 1차 타겟 검증 후 진입 |

| 순위 | 세그먼트 | 진입 조건 |

## 2-4. 지금은 타겟이 아닌 사용자

퍼널 효율을 위해 명시적으로 제외합니다.

| 제외 대상 | 이유 |
| --- | --- |
| 빠른 산출물만 원하는 사용자 | 제품 원칙(선작성·후개입)과 정면으로 충돌. 유입되어도 ⑥ Activation에서 100% 이탈 |
| 이미 사고 절차가 체화된 시니어 | 10단계 가이드가 오히려 마찰. 다만 ⑩ 포트폴리오 전환만 필요로 할 가능성은 있음 |
| 기업 내부 데이터를 다루려는 사용자 | 로컬 저장 기반 · 민감 정보 처리 정책 미확정 |
| 협업·팀 단위 사용 | 실시간 협업은 현재 제외 범위 |

## 3. 검증이 필요한 가정

이 USP와 타겟 정의는 문서 기반 정리이며, 아래는 아직 사용자 검증 전입니다.

- 취준생·직무 전환자가 **10단계라는 마찰을 실제로 감수하는가**
- 첫 성공 순간을 "첫 단계 저장" / "Case 완료" / "포트폴리오 생성" 중 무엇으로 정의할 것인가 *(원본 Open Decision)*
- 대표 사용자를 취업준비생·직무 전환자에 얼마나 오래 집중할 것인가 *(원본 Open Decision)*
- 성장 metric을 사용자에게 **언제, 어떤 설명과 함께** 노출할 것인가 *(원본 Open Decision)*
- 공개 포트폴리오 기능을 MVP에 포함할 것인가 *(원본 Open Decision)*
- 지불 의사가 **포트폴리오 전환 시점**에 실제로 발생하는가 *(퍼널 가설, 원본 문서에 결제는 제외 범위로 명시됨)*
