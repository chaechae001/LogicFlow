# 정보 구조와 화면 설계

기존 폴더(`E:\thinking_flow`)의 구조·디자인은 참고하지 않고 처음부터 다시 짰다.
설계 근거는 `references\논리적 사고력 키우기_Insight.md` 와 `논리적 사고 훈련 시스템 구조안.pdf` 의 10단계 FLOW·목적별 모듈·통합 템플릿이다.

---

## 1. 이전 구조에서 바꾼 것

| 문제 | 새 구조의 처리 |
| --- | --- |
| 화면이 많고 진입 경로가 갈라진다 | **화면 5개**로 줄였다. 랜딩 · 시작 · 작업 · 저장소 · 결과물 |
| 작업 화면에 정보가 한꺼번에 쏟아진다 | **질문을 한 번에 하나만** 보여준다. 나머지는 접힌 상태로 대기 |
| 빈 텍스트 상자 앞에서 막힌다 | 자유 입력 대신 **질문 → 선택지 → 문장 조립기 → 도식 빌더** 순으로 마찰을 낮춘다 |
| 10단계가 항상 강제된다 | **템플릿이 단계 수를 정한다.** 1단계짜리도, 10단계짜리도 같은 엔진 |
| 사고 과정이 글자로만 남는다 | **단계마다 다른 인포그래픽**이 실시간으로 그려진다 |
| 훈련 기록과 포트폴리오가 따로 논다 | 관찰 → 질문 → 케이스 → 결과물의 **단일 승격 경로** |

## 2. 사이트맵

```
/                        랜딩
/start                   훈련 시작 — 목적 · 주제 · 템플릿
  /start/topics          주제 탐색 (오늘의 이슈 · 산업/기업 · 문제 유형 · 내 저장소)
/case/:id/:step          작업 화면 ★ 핵심
/case/:id/map            전체 사고 도식 (한 장)
/case/:id/output         결과물 변환
/library                 저장소
  /library/insight       관찰 저장소
  /library/question      질문 저장소
  /library/case          사고 케이스 목록
/plan                    훈련 플랜 (1일 · 1주 · 1개월)
/me                      성장 리포트
```

시안으로 만든 것: 랜딩 · 시작 · 작업 · 저장소 · 도식+결과물 (5개).
`/plan` 은 랜딩의 "훈련 리듬" 섹션과 저장소 상단에 요약 형태로 들어가 있고, 별도 화면은 2차 범위다.

## 3. 화면별 설계

### 3.1 랜딩 — `landing.html`

**단일 목표**: 3초 안에 "AI가 답을 대신 써주는 서비스가 아니다"를 이해시키고 `/start`로 보낸다.

**히어로 결정** — 헤드라인 + CTA + 추상 일러스트 대신, **제품의 실제 동작을 히어로에 그대로 넣었다.**
한 줄 문제 정의 카드 → 로직 트리 4갈래 → 근거 없는 가지에 형광 표시 → 코치의 한 줄.
이 서비스에서 가장 특징적인 장면이 그것이기 때문이다. 설명하는 대신 보여준다.

| 섹션 | 역할 |
| --- | --- |
| 히어로 | 동작하는 미니어처. 문제 정의 → 분해 → 공백 표시 |
| 01 왜 안 느나 | 증상 3개. "첫 줄이 안 써진다 / 섞인다 / 판단이 안 남는다" |
| 02 작동 방식 | **8개 단계 탭.** 각 단계의 질문과 **그 단계에 그려지는 인포그래픽**을 실제로 보여준다 |
| 03 무엇으로 훈련할까 | 진입 3방식 — 내 문제 / 오늘의 이슈 / 산업·기업 |
| 04 훈련 리듬 | 1일 20분 · 1주 7단계 · 1개월 10단계 |
| 05 기록이 자라는 경로 | 관찰 → 질문 → 케이스 → 결과물 |
| 06 누가 쓰나 | 기획 · PM · 분석 · DS · 개발 |
| 마무리 | "오늘 걸렸던 문제 하나면 충분합니다" |

### 3.2 훈련 시작 — `start.html`

세 개의 번호 붙은 시트. 번호를 쓴 이유는 실제로 순서가 있는 절차이기 때문이다.

| 시트 | 내용 |
| --- | --- |
| **01 목적** | 8개 모듈 카드. 카드마다 포함 단계 수와 예상 시간을 미리 보여준다 |
| **02 주제** | 4개 소스 탭 — 내 문제 적기 / 오늘의 이슈 / 산업·기업 / 내 저장소에서 |
| **03 템플릿** | 4개 프리셋 + **단계 on/off 칩 10개** + 도움 정도 3단계 |

하단에 **선택 요약 바가 sticky**로 붙어, 무엇을 고르는 중인지 늘 보인다.

**지켜야 할 규칙** — 시작 전에 답을 요구하지 않는다. 첫 생각은 1단계 안에서 쓴다.
"오늘의 이슈"는 공개 자료 기준으로만 만들고, 확인되지 않은 내부 수치는 `가상 설정` / `내부 수치 없음` 배지로 구분한다.

### 3.3 작업 화면 — `workspace.html` ★

**3존 구조**

```
┌─────────────────────────────────────────────────────────────┐
│ 앱바 — 케이스명 · 템플릿 · n/N · 저장 상태 · 전체 도식 · 완료 │
├───────────┬─────────────────────────────┬───────────────────┤
│ 단계 레일 │  단계 헤더 (번호·목적)      │ 실무 예시         │
│ (224px)   │  쓰기 방식 전환             │ 코치              │
│           │  ┌───────────────────────┐  │ 내 저장소         │
│ 진행 점   │  │ 질문 n/N  (한 번에 1개)│ │ (316px, 탭)       │
│ 쌓인 것   │  │ 선택지 · 조립기 · 빌더 │ │                   │
│           │  └───────────────────────┘  │                   │
│           │  ┌───────────────────────┐  │                   │
│           │  │ 지금까지 그려진 도식  │  │                   │
│           │  │ + 점검 배지           │  │                   │
│           │  └───────────────────────┘  │                   │
└───────────┴─────────────────────────────┴───────────────────┘
```

**막막함을 없애는 장치 6개**

1. **질문 한 번에 하나** — 빈 상자 대신 질문 카드. 상단에 `질문 2 / 4` 진행 표시.
2. **선택지 우선** — 답을 쓰기 전에 고르게 한다. (분해 기준 6개 칩 등)
3. **문장 조립기** — 한 줄 문제 정의는 5칸 빈칸 채우기. 빈 칸이 남으면 무엇이 비었는지 눈에 보인다.
4. **도식 빌더** — 로직 트리는 텍스트가 아니라 노드 추가 UI로 만든다.
5. **예시는 옆에** — 입력란에 미리 채우지 않는다. 오른쪽 패널에 `참고용` 배지와 함께 놓는다.
6. **코치 버튼 3개** — 「막혔어요」「더 넓게 보고 싶어요」「이거 맞나요?」 그 이상 만들지 않는다.

**코치 규칙**

- 사용자가 한 글자도 쓰지 않았으면 켜지지 않는다.
- 답을 대신 쓰지 않는다. 빠진 것·겹치는 것·근거 없는 것만 짚는다.
- 「반영함 / 반영 안 함」을 남긴다. **반영하지 않은 기록도 판단 데이터다.**

**쓰기 방식** — `질문 따라가기` ↔ `자유 작성` 두 가지. 전환해도 양쪽 내용이 남는다.

**단계 이동과 완료는 분리** — 비어 있어도 다음 단계로 갈 수 있다. 비어 있는 항목은 마지막 회고에서 모아 보여준다.

### 3.4 저장소 — `library.html`

세 개의 DB를 탭으로 나눴고, 상단에 승격 경로를 항상 노출한다.

**관찰 저장소 (Insight DB)**
- 상단 **두 줄 캡처 박스**가 화면의 주인공이다. 마찰이 크면 아무도 안 쌓는다.
- 입력 시 딱 두 가지만 고른다: `직접 본 사실` / `내 해석`, 그리고 출처(일상·수업·뉴스·업무·프로젝트).
- **비슷한 기록 n회** 배지 — 반복해서 적은 것이 곧 진짜 문제다. 이 배지가 "문제로 키우기" 버튼의 근거가 된다.
- 액션: `문제로 키우기`(→ 케이스 생성) / `질문으로`(→ Question DB) / `사실로 바꾸기`

**질문 저장소 (Question DB)**
- 단계별로 묶어 보여준다. 작업 화면에서 **현재 단계에 해당하는 질문만** 추려 노출한다.
- 출처 구분: 내가 쓴 것 / 코치가 던진 것.
- 즐겨찾기한 질문은 해당 단계 진입 시 자동으로 상단에 뜬다.

**사고 케이스 (Case DB)**
- 진행률 미터, 수정 횟수, 코치 점검 횟수. 완료된 것은 결과물로 이동.

### 3.5 전체 도식과 결과물 — `portfolio.html`

**상단: 케이스 맵** — 10단계를 5×2 격자 한 장으로. 각 칸에 그 단계의 요약 한 문장 + 상태 태그.
논리 공백이 있는 칸은 형광 배경으로 칠한다. 칸을 누르면 그 단계의 실제 문장과 수정 이력으로 간다.

**하단: 결과물 변환** — 좌측 5개 유형, 우측 문서 미리보기.

| 유형 | 구조 |
| --- | --- |
| 논리형 포트폴리오 | 배경 → 관찰 → 문제 정의 → 구조 → 가설·검증 → 대안·결정 → **한계** |
| 서비스 분석 글 | 800~1,200자, 문제–탐색–검증–학습 |
| 면접 답변 (경험형) | 상황 → 문제 정의 → 접근 → 결과·배운 점 + 예상 후속 질문 |
| 기획서 초안 | 문제 → 제안 → 성공 기준 → 검토하지 않은 것 |
| 기술 블로그 | 서사형. 틀린 가설을 접은 지점을 중심으로 |

**변환 규칙 (지켜야 할 선)**

- 원본에 있는 것만 쓴다. 성과·역할·수치를 새로 만들지 않는다.
- 문장에 점선 밑줄 → 마우스 올리면 `STEP 03 · 응답 v5` 처럼 **출처 단계와 버전**이 뜬다.
- "계획"과 "실제 실행 결과"를 구분해 표시한다.
- 원본을 고치면 변환 문서에 "원본이 바뀌었습니다" 표시가 붙는다.
- 기본 공개 범위는 비공개. 게시 전 기업명·개인정보·내부 자료 포함 여부를 확인한다.

## 4. 단계별 인포그래픽 규격

**단계마다 그려지는 그림의 형태가 다르다.** 같은 그림을 계속 보여주면 진행 실감이 사라지고, 단계 고유의 사고 방식도 전달되지 않는다.

> **10단계 전부 [`mockups/workspace.html`](mockups/workspace.html)에 구현되어 있다.**
> 왼쪽 레일에서 단계를 누르면 그 단계의 질문 카드와 인포그래픽으로 바뀐다. 오른쪽 실무 예시도 함께 바뀐다.

| # | 단계 | 그려지는 것 | 완료 판정에 쓰는 신호 |
| ---: | --- | --- | --- |
| 01 | 목적·맥락 이해 | **맥락 카드** — 주제·목표·핵심 지표·이해관계자·제약·지금인 이유 6행. 빈 행은 “아직 안 적음”으로 남긴다 | 6행 중 5행 이상 채움 |
| 02 | 현상 관찰 | **사실 / 해석 / 미확인 3열 보드** — 항목마다 칸을 옮길 수 있다 | 사실 3개 이상, 사실·해석 분리됨 |
| 03 | 문제 정의 | **한 줄 조립 바 + 품질 체크 6항목** — 5칸 슬롯이 한 문장으로 이어지고, 아래에 품질 기준 통과 여부 | 5칸 전부 채움, 해결책 어휘 미포함 |
| 04 | 문제 분해 | **로직 트리 + MECE 점검 표** — 가지별 하위 요소·측정 지표·상태를 표로 병기 | 가지 3~5개, 중복 경고 해소 |
| 05 | 가설 설정 | **가설 카드 덱** — 원인(보라) · 해결(초록) · 지표(파랑) · 백업(회색) 4색 | 원인 가설 3개 + 백업 1개 |
| 06 | 근거·검증 | **검증 매트릭스** — 가설 × 보일 현상 × 데이터 × 방법 × 판단 기준 × 결과 | 모든 가설에 판단 기준 있음 |
| 07 | 대안·의사결정 | **비교 스코어 표** — 기준별 막대 + 선택 행 강조 + 결론 문장 카드 | 대안 3개 이상, 기준을 대안보다 먼저 정의 |
| 08 | 해결안 설계 | **사용자 FLOW 체인** — 기존/신규 칸을 색으로 구분, 아래에 기능·정책·데이터·예외 표 | 흐름 시작과 끝이 이어짐 |
| 09 | 결과 평가 | **Before/After 지표 카드 + 가설 판정 배지** — 가드레일 지표는 별도 색 | 성공 기준과 가드레일 지표 존재 |
| 10 | 결론·회고 | **논리 체인 한 장 + 전달 구조 표** — 10칸 중 끊긴 구간을 주의색으로 | 회고 질문 응답 완료 |

**공통 규칙**

- 도식은 사용자가 답할 때마다 즉시 갱신된다. 별도 "생성" 버튼이 없다.
- 비어 있는 부분은 숨기지 않는다. 회색 자리로 남겨 무엇이 빠졌는지 보이게 한다.
- 도식 아래 **점검 배지 줄**을 둔다. `✓ 통과` / `! 경고` / `미입력 n개` 세 종류만.
- 경고는 차단하지 않는다. 넘어갈 수 있고, 넘어간 기록도 남는다.

## 5. 화면 상태 정의

작업 화면이 가져야 하는 상태. 시안에는 대표 상태만 그렸다.

| 상태 | 표시 |
| --- | --- |
| 아직 안 씀 | 질문 카드만, 도식은 회색 자리 |
| 쓰는 중 | 저장 상태 `저장 중…` |
| 저장됨 | `n분 전 저장됨` (초록 점) |
| 저장 실패 | 재시도 버튼, 입력 내용 유지 |
| 코치 잠김 | 코치 탭에 "먼저 몇 줄 써주세요" |
| 코치 응답 중 | 버튼 비활성 + 진행 표시 |
| 점검 결과 있음 | 형광 테두리 메시지 + 반영/미반영 버튼 |
| 경고 있는 채로 이동 | 확인 다이얼로그 1회, "계속 이동" 항상 가능 |
| 과거 버전 보기 | 현재 응답 위에 버전 목록 |

## 7. 접근성 기준

- 모든 입력에 라벨. 도식 노드 입력에도 `aria-label`.
- 상태를 색으로만 표시하지 않는다. 태그에 항상 텍스트(`사실`, `가설`, `논리 공백`)를 같이 쓴다.
- 키보드 이동 순서: 단계 레일 → 질문 카드 → 도식 → 오른쪽 패널.
- `:focus-visible` 아웃라인을 주색으로 명확히 표시.
- 저장 상태와 코치 응답은 live region으로 읽어준다.
- `prefers-reduced-motion` 존중 (전환 애니메이션 제거).
