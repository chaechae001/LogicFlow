# 디자인 시스템 v2

구현: [`mockups/app.css`](mockups/app.css) · 미리보기: [`mockups/index.html`](mockups/index.html)

> **v2에서 바뀐 것**
> 1. 형광 노랑연두(`#DDF25C`)를 걷어내고 부드러운 테라코타로 교체했습니다. 눈이 아프다는 지적이 맞았습니다.
> 2. 전체 색조를 초록빛 본색에서 **저채도 청회색**으로 바꾸고 본문 대비를 올렸습니다.
> 3. 메뉴가 전부 같은 색이던 문제를 **세 개의 독립된 카테고리 색 체계**로 나눴습니다.

## 1. 디자인 방향 — "제도 도면 (Schematic sheet)"

이 서비스의 세계는 노트나 채팅이 아니라 **도면**입니다. 로직 트리, 분기선, 검증 표, 비교 매트릭스.
재료는 **선 · 노드 · 분기 · 표** 네 가지이고, 화면 전체를 한 장의 제도 용지처럼 다룹니다.

**의도적으로 피한 것**

| 흔한 선택 | 왜 안 썼나 |
| --- | --- |
| 크림색 배경 + 세리프 제목 + 테라코타 포인트 | 요즘 AI 도구가 전부 쓰는 조합. 주제와 무관하게 나온다 |
| 검정 배경 + 형광 초록 | 개발자 도구 클리셰. 학습 서비스의 차분함과 안 맞는다 |
| 그라디언트 · 글래스모피즘 · 3D 일러스트 | 이 제품의 재료는 선과 표다. 장식이 도식을 방해한다 |
| 큰 숫자 + 작은 라벨 히어로 | 보여줄 성과 지표가 아직 없다. 대신 제품 동작을 히어로에 넣었다 |

## 2. 왜 색을 바꿨나

v1은 초록빛이 도는 본색 종이(`#EFF1EC`)에 형광 노랑연두를 강조로 썼습니다. 세 가지 문제가 있었습니다.

| 문제 | 원인 | v2의 처리 |
| --- | --- | --- |
| 눈이 아프다 | 형광 `#DDF25C`는 명도·채도가 동시에 최고치. 논리적 사고처럼 오래 머무는 화면에 부적합 | 테라코타 `#B05A3C` + 옅은 배경 `#FAEAE3`. 명도를 낮추고 채도만 남김 |
| 눈에 잘 안 들어온다 | 본문 `#1A1714`와 배경의 대비는 충분했으나, 보조 텍스트와 헤어라인이 너무 옅어 위계가 사라짐 | 본문 `#1B2430`, 보조 `#66717F`, 테두리 `#E0E5EB`로 각 단계 대비를 벌림 |
| 전체가 탁하다 | 초록 기 도는 회색은 잉크 청록과 섞여 색조가 하나로 뭉갬 | 배경을 **중립에 가까운 청회색** `#F6F7F9`로. 색은 콘텐츠에만 남김 |

**논리적 사고에 어울리는 색이 무엇인가** — 오래 앉아서 읽고 쓰는 화면입니다.
채도가 낮은 청색 계열이 피로가 가장 적고, 분석·판단의 톤과도 맞습니다.
그래서 주색을 **스틸 블루 `#2A5A87`** 로 잡고, 나머지는 전부 무채색에 가깝게 눌렀습니다.

## 3. 색 체계 — 다섯 개, 서로 섞지 않는다

색이 많으면 무지개가 되고, 적으면 구분이 안 됩니다. 그래서 **체계를 다섯으로 나누고 각각 쓰이는 자리를 고정**했습니다.

| 체계 | 어디에 | 모양 | 축 |
| --- | --- | --- | --- |
| 의미 태그 | 작업 화면 안의 **내용** | 알약 + 점 | 사실 · 해석 · 가설 · 근거 · 미확인 · 공백 |
| 훈련 계열 | 시작 화면, 단계 레일 | **왼쪽 색 막대** | 정의 · 구조 · 검증 · 표현 |
| 난이도 | 모듈 카드, 케이스 목록 | 색 + **막대 개수** | 입문 → 도전 (순서 있음) |
| 산업 | 주제 선택, 케이스 목록 | 왼쪽 색 막대 | 6종 |
| 주색 / 주의색 | 버튼·활성 / 논리 공백 | 면 채움 / 테두리 | — |

> **한 화면에 색 체계는 최대 두 개.**
> 작업 화면 = 의미 태그 + 훈련 계열. 시작 화면 = 훈련 계열 + 난이도 + 산업 (의미 태그는 나오지 않음).
> 의미 태그와 카테고리는 **모양이 다르므로**(알약 vs 왼쪽 막대) 색이 겹쳐도 혼동되지 않습니다.

### 3.1 기본

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--paper` | `#F6F7F9` | 앱 배경 |
| `--surface` | `#FFFFFF` | 카드·시트 |
| `--surface-2` | `#F0F2F6` | 표 헤더, 보조 패널 |
| `--rule` | `#E0E5EB` | 헤어라인 |
| `--rule-strong` | `#C2C9D4` | 도식 연결선 |
| `--ink` | `#1B2430` | 본문 |
| `--ink-2` | `#3B4655` | 도식 안 텍스트 |
| `--muted` | `#66717F` | 보조 |
| `--faint` | `#949CA8` | 캡션 |

### 3.2 주색 · 주의색

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--deep` | `#2A5A87` | 버튼, 활성 단계, 링크, 루트 노드 |
| `--deep-wash` | `#E4EDF5` | 선택 상태 배경 |
| `--attn` | `#B05A3C` | **논리 공백과 코치 지적 전용** |
| `--attn-bg` | `#FAEAE3` | 주의 블록 배경 |
| `--attn-soft` | `#F2DCD2` | 텍스트 밑칠 (`<mark>`) |

주의색을 강조·장식·CTA에 쓰지 않습니다. 다른 곳에 쓰는 순간 "여기 문제 있다"는 신호가 죽습니다.

### 3.3 의미 태그 — 작업 화면 내용 전용

| 태그 | 값 | 뜻 |
| --- | --- | --- |
| 사실 | `#2E6B58` | 직접 확인한 행동·수치·발언 |
| 해석 | `#8A6A1F` | 그 사실이 의미한다고 본 것 |
| 가설 | `#5B4AA0` | 검증 전 추정 |
| 근거 | `#1F6D93` | 가설을 지지·기각한 자료 |
| 미확인 | `#6B7480` | 아직 확인하지 못한 것 |
| 논리 공백 | `#B05A3C` | 주장은 있는데 근거가 없는 지점 |

사실·해석 분리는 이 제품의 핵심 훈련이므로, 색이 아니라 **어휘로 먼저 존재**합니다. 태그에는 언제나 텍스트를 함께 씁니다.

### 3.4 훈련 계열 — 10단계를 네 묶음으로

참고 자료가 정리한 네 가지 훈련(문제 정의 → 구조화·가설 → 근거 기반 의사결정 → 글·말·포트폴리오 표현)을 그대로 색으로 옮겼습니다. 임의로 만든 분류가 아닙니다.

| 계열 | 값 | 단계 |
| --- | --- | --- |
| 정의 | `#2F7A63` | 01 목적·맥락 · 02 현상 관찰 · 03 문제 정의 |
| 구조 | `#2A6E9E` | 04 문제 분해 |
| 검증 | `#6A4FA3` | 05 가설 · 06 근거·검증 · 07 대안·의사결정 |
| 표현 | `#B4703C` | 08 해결안 설계 · 09 결과 평가 · 10 결론·회고 |

작업 화면 왼쪽 레일의 각 단계 앞에 이 색이 3px 막대로 붙어, 지금 어느 훈련을 하는 중인지 항상 보입니다.

### 3.5 난이도 — 색과 개수를 함께

| 단계 | 값 | 표시 |
| --- | --- | --- |
| 입문 | `#5B8C6E` | ▮▯▯▯ |
| 기본 | `#3D7EA6` | ▮▮▯▯ |
| 심화 | `#6A5AA8` | ▮▮▮▯ |
| 도전 | `#A0526E` | ▮▮▮▮ |

난이도는 **순서가 있는 값**이므로 색만으로 두지 않고 채워진 막대 개수로도 읽히게 했습니다. 색각 이상이 있어도 구분됩니다.

### 3.6 산업

커머스 `#B4703C` · 핀테크 `#2A6E8C` · 콘텐츠·OTT `#8E4E7A` · B2B SaaS `#3E7A5E` · 플랫폼·O2O `#6A5AA8` · HR·교육 `#8A6A2A`

**문제 유형**(전환율 하락, 지표 설계 등)에는 색을 주지 않고 회색 칩으로 둡니다. 색 축을 셋으로 제한해야 화면이 무지개가 되지 않습니다.

### 3.7 다크 모드

`prefers-color-scheme: dark`로 전 토큰을 치환합니다. 카테고리 색은 명도를 올려 어두운 배경에서 분리되게 합니다.

## 4. 타이포그래피

| 역할 | 서체 | 쓰는 곳 |
| --- | --- | --- |
| **Display** | Bricolage Grotesque 800 | **라틴·숫자 전용.** 워드마크, 큰 단계 번호, `4 / 10` |
| **Body / Heading** | IBM Plex Sans KR 400·600·700 | 한글 제목과 본문 전부 |
| **Utility** | IBM Plex Mono 500 | 라벨, 단계 키, 표 헤더, 지표, 날짜 |

- 한글 제목을 Bricolage에 맡기지 않습니다. 글리프가 없어 폴백이 섞이면 지저분해집니다. **라틴은 Bricolage, 한글은 Plex Sans KR**로 역할을 나눴습니다.
- 라벨(`.label`)은 대문자 + `letter-spacing: .13em`. 도면의 섹션 콜아웃처럼 **선 위에 얹습니다.**
- 제목 자간 `-0.022em`. 한글은 기본 자간이 넓어 조여야 단단해 보입니다.
- 본문 줄간 1.65~1.72. 사고를 읽는 화면이라 촘촘하면 안 됩니다.
- 표의 숫자는 `tabular-nums`.

## 5. 시그니처 요소 — 커넥터 선

로직 트리의 `├─ └─` 분기선을 CSS 의사요소로 그립니다. 장식이 아니라 **정보 구조 그 자체**입니다.
같은 선 언어를 세 곳에서 반복합니다.

1. **로직 트리** (`.tree`) — 문제 분해. 부모-자식 관계를 선으로
2. **단계 레일** (`.rail`) — 10단계가 하나의 세로선에 꿰어진다
3. **케이스 맵** (`.maprow`) — 전체 도식. 칸과 칸을 화살촉으로

선 굵기는 전부 1px, 색은 `--rule-strong` 하나. 굵기나 색으로 위계를 만들지 않습니다.

## 8. 모션

거의 쓰지 않습니다. 도면이 움직일 이유가 없습니다.

- 호버 시 카드 `translateY(-2px)` + 테두리 색 변화 (140ms)
- 탭 전환은 즉시. 페이드 없음
- 도식 갱신만 예외적으로 부드럽게 — 답한 결과가 그림이 되는 순간이라 이 하나는 보여줄 값어치가 있습니다
- `prefers-reduced-motion: reduce`에서 전부 제거

## 9. 보이스 & 마이크로카피

**원칙** — 코치는 사람인 척하지 않습니다. 사과하지 않고, 칭찬하지 않고, 짚기만 합니다.

| 상황 | 이렇게 | 이렇게 말고 |
| --- | --- | --- |
| 코치 지적 | "네 번째 가지 ‘제품 자체’는 사용자 유형이 아닙니다." | "좋은 시도예요! 다만 조금 아쉬운 점이…" |
| 빈 상태 | "관찰 한 줄이면 1단계를 시작할 수 있습니다." | "아직 아무것도 없어요 😢" |
| 경고 | "기준이 둘로 섞이면 어느 가지부터 볼지 정할 수 없습니다." | "MECE 위반이 감지되었습니다" |
| 저장 실패 | "저장하지 못했습니다. 쓰신 내용은 그대로 있습니다. 다시 시도" | "오류가 발생했습니다" |
| 버튼 | `단계 완료` → 완료 후 `완료됨` | `제출` / `확인` |

- 동사는 사용자가 하는 일로 적습니다. `문제로 키우기`, `질문 가져오기`, `가지로 추가`.
- 예시에는 항상 `참고용` 배지.
- 시스템 용어를 노출하지 않습니다.

## 10. 품질 기준

- 모바일 375px까지 가로 스크롤 없음. 표와 도식만 자체 `overflow-x: auto`
- 키보드 포커스 링 항상 보임
- 색 대비: 본문 4.5:1 이상, 라벨 3:1 이상
- 상태를 색으로만 표시하지 않음 — 태그에 텍스트, 난이도에 막대 개수
- 다크 모드에서 모든 카테고리 색이 배경과 분리되는지 확인
