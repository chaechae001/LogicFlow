# 10단계 학습 모델과 Workspace 정렬 기준

> 기존 10단계→8개 Workspace 통합안은 폐기된 검토안이다.

## 1. 확정된 10단계

| 순서 | Stage 표시명 | 핵심 목적 |
|---:|---|---|
| 1 | 목적·맥락 이해 | 상황, 목표, 이해관계자, 제약, 지금 다루는 이유 |
| 2 | 현상 관찰 | 확인된 사실, 행동, 지표, 해석, 미확인 사항 분리 |
| 3 | 문제 정의 | 대상, 상황, 목표 행동, 장애, 영향 정의 |
| 4 | 문제 분해·구조화 | 분해 기준, Logic Tree, Journey, 누락·중복 점검 |
| 5 | 가설 설정 | 원인·해결·결과·백업 가설 작성 |
| 6 | 근거 수집·검증 | 데이터, 지표, 검증 방법, 대상·기간, 판단 기준 |
| 7 | 대안 비교·의사결정 | 대안, 비교 기준, 트레이드오프, 최종 선택 |
| 8 | 해결안 설계·실행 | 기능·정책·프로세스·실행 순서·리스크 설계 |
| 9 | 결과 평가 | 실제 결과 또는 검증 계획, 부작용, 후속 검증 |
| 10 | 결론 전달·회고 | 결론, 핵심 근거, 판단 변화, 배움, 다음 행동 |

## 2. Workspace 원칙

- 왼쪽 내비게이션은 10개 단계다.
- 진행률은 `n/10`으로 표시한다.
- Thinking Case 생성 시 10개의 CaseStep을 수용해야 한다.
- 각 단계는 고유 stage key와 route를 가진다.
- 질문이나 카드 그룹은 단계 내부에서 묶을 수 있지만 단계 자체는 합치지 않는다.

## 3. 권장 stage key

최종 key는 기존 코드 관례를 검토한 뒤 확정한다.

```text
context
observation
problem_definition
problem_structuring
hypothesis
validation
decision
solution_execution
result_evaluation
conclusion_reflection
```

Codex는 기존 key와 route 사용 위치를 분석하고, 호환성과 가독성을 고려한 최종안을 먼저 보고한다.

## 4. 작성 방식 공통 구조

모든 단계는 동일한 작성 방식 선택을 제공한다.

```text
unselected
freeform
structured
```

- 자유 작성: 큰 입력 영역에서 생각을 자유롭게 기록
- 구조화 입력: 단계별 질문 또는 카드에 따라 기록
- 사용자는 두 방식을 바꾸거나 함께 사용할 수 있음
- 기존 작성 내용은 보존

Task 04에서는 선택 UI와 시각적 상태를 구현한다. 실제 입력 저장, 전환 보존, 버전 생성은 Task 05 이후다.

## 5. AI Coach 상태

- 입력 전: 비활성 empty state
- 사용자 입력 후: 점검 요청 가능 상태
- 실제 AI 호출: Task 05 이후

Task 04에서는 활성·비활성 상태가 수용될 UI 구조와 문구만 구현한다.
