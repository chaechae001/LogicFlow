# Thinking Flow V2 — Stage Templates

## 1. 문서 사용법

이 문서는 단계별 작성 UI와 학습 콘텐츠를 설계하기 위한 후보 템플릿이다. 질문 수, 필수 질문, 완료 조건은 아직 제품 결정이 아니며 구현 전에 검증해야 한다.

예시는 “오프라인에서 체험한 상품을 앱에서 다시 찾고 비교하는 여정을 개선한다”는 가상 Practice Case로 연결한다. 특정 기업의 실제 고객 행동이나 내부 수치를 뜻하지 않으며, 좋은 예시도 정답이 아니라 **주장 상태와 사고 구조가 드러나는 문장**을 보여준다.

공통 원칙:

- 한 번에 `freeform` 또는 `structured` 하나의 UI만 활성화한다.
- 전환해도 양쪽의 저장된 내용을 삭제하지 않는다.
- 기본 권장 흐름은 짧은 자유 작성 후 구조화 질문으로 빠진 요소를 보완하는 방식이다. 단, 사용자는 처음부터 구조화 입력을 선택할 수 있다.
- 좋은 예시는 사용자가 작성하기 전에 정답처럼 자동 삽입하지 않는다.
- “필수”는 완료 판단 후보이며 이동 자체를 막지 않는다.

## 2. 단계별 템플릿

### 1. `context` — 목적·맥락 이해

- **자유 작성 안내**: 이 Case를 왜 다루며 누구의 어떤 결정을 돕는지, 범위와 제약을 먼저 적는다.
- **구조화 질문(4개)**:
  1. **[필수 후보]** 이번 Case에서 달성하거나 판단하려는 목적은 무엇인가?
  2. **[필수 후보]** 주요 사용자·요청자·이해관계자는 누구인가?
  3. 포함할 범위와 제외할 범위는 무엇인가?
  4. 알려진 전제, 제약, 아직 확인할 가정은 무엇인가?
- **좋은 예시**: “목적은 오프라인 체험 뒤 앱에서 상품을 다시 찾는 여정의 마찰을 정의하고, 작은 검증안을 선택하는 것이다. 실제 이탈률은 알 수 없으므로 행동 규모는 가정하지 않는다.”
- **좋지 않은 예시**: “QR 기능을 추가해 매출을 올린다.”
- **자주 하는 실수**: 수단을 목적처럼 쓰기, 이해관계자 누락, 가정을 사실로 표현.
- **placeholder**: “이번 Case가 답해야 할 결정, 범위, 제약을 내 말로 정리해보세요.”
- **도움말**: 목적은 “무엇을 만들까”보다 “어떤 판단을 왜 내려야 하나”에 가깝다.
- **최소 산출물**: 목적 1개, 핵심 이해관계자, 범위, 미확인 가정.
- **완료 조건 후보**: 필수 후보 2개 응답과 최소 산출물 존재.
- **포트폴리오 연결**: Case 개요, 배경과 목적, 내 역할.

### 2. `observation` — 현상 관찰

- **자유 작성 안내**: 확인한 사실, 그 사실에 대한 해석, 아직 모르는 정보를 구분해 적는다.
- **구조화 질문(4개)**:
  1. **[필수 후보]** 직접 확인했거나 Case가 제공한 현상은 무엇이며 출처는 무엇인가?
  2. **[필수 후보]** 그 현상에서 내가 해석한 내용은 무엇인가?
  3. 반대 사례나 다른 해석은 무엇인가?
  4. 문제를 판단하려면 어떤 정보가 더 필요한가?
- **좋은 예시**: “가상 인터뷰 기록에는 ‘앱에서 같은 상품을 다시 찾기 어려웠다’는 진술이 있다(제공 자료). 이것이 다수 고객의 공통 행동인지는 확인되지 않았다.”
- **좋지 않은 예시**: “모든 고객이 앱 검색을 불편해한다.”
- **자주 하는 실수**: 표본을 전체로 일반화, 원인을 관찰에 섞기, 출처 생략.
- **placeholder**: “확인한 것 / 내가 해석한 것 / 아직 모르는 것을 나눠 적어보세요.”
- **도움말**: 관찰 문장에 “때문에”가 들어가면 원인 해석인지 점검한다.
- **최소 산출물**: 출처가 있는 관찰, 해석, 정보 공백 각 1개 이상.
- **완료 조건 후보**: 필수 후보 응답과 사실·해석 상태 구분.
- **포트폴리오 연결**: 관찰한 현상, 데이터·출처, 불확실성.

### 3. `problem_definition` — 문제 정의

- **자유 작성 안내**: 누구의 어떤 상황에서 어떤 목표가 막히며, 이번 Case가 답할 핵심 질문이 무엇인지 쓴다.
- **구조화 질문(4개)**:
  1. **[필수 후보]** 문제를 겪는 사용자와 구체적 상황은 무엇인가?
  2. **[필수 후보]** 사용자의 목표와 그것을 막는 마찰은 무엇인가?
  3. 이 문제가 중요하다고 판단하는 근거와 영향은 무엇인가?
  4. 해결안 표현을 제외한 핵심 의사결정 질문은 무엇인가?
- **좋은 예시**: “오프라인 체험 뒤 앱에서 후보를 다시 비교하려는 사용자가 같은 상품을 다시 찾는 과정에서 어려움을 겪는다는 제공 자료의 관찰을 바탕으로, 어느 지점에서 마찰이 생기는지 검증해야 한다.”
- **좋지 않은 예시**: “매장에 QR을 설치하지 않은 것이 문제다.”
- **자주 하는 실수**: 해결안을 문제로 고정, 사용자·상황 누락, 여러 문제 결합.
- **placeholder**: “[누가] [어떤 상황에서] [무엇을 하려 하지만] [어떤 마찰을 겪는다].”
- **도움말**: 문제 문장을 읽었을 때 서로 다른 해결안이 두 개 이상 나올 수 있어야 한다.
- **최소 산출물**: 문제 문장 1개와 핵심 질문 1개.
- **완료 조건 후보**: 필수 후보 응답, 관찰과 연결, 특정 기능명에 종속되지 않음.
- **포트폴리오 연결**: 문제 정의, 중요성, 핵심 질문.

### 4. `problem_structuring` — 문제 분해·구조화

- **자유 작성 안내**: 핵심 문제를 하나의 일관된 축으로 나누고 우선 탐색할 영역을 고른다.
- **구조화 질문(4개)**:
  1. **[필수 후보]** 문제를 어떤 기준으로 하위 문제로 나눌 것인가?
  2. **[필수 후보]** 하위 문제와 그 관계는 무엇인가?
  3. 누락·중복되거나 수준이 맞지 않는 항목은 없는가?
  4. 먼저 탐색할 영역과 선택 이유는 무엇인가?
- **좋은 예시**: “여정을 기억–재탐색–비교–구매로 나누고, 현재 자료가 있는 재탐색 구간을 우선 검증한다.”
- **좋지 않은 예시**: “QR, 추천, 쿠폰 기능을 세 갈래 문제로 나눈다.”
- **자주 하는 실수**: 문제와 해결안 축 혼용, MECE 형식에 집착, 우선순위 근거 누락.
- **placeholder**: “문제 구조를 2~4개의 하위 영역과 관계로 설명해보세요.”
- **도움말**: 각 가지가 같은 질문에 답하는 동일 수준인지 확인한다.
- **최소 산출물**: 문제 구조와 우선 영역 및 이유.
- **완료 조건 후보**: 필수 후보 응답과 문제 정의의 추적 가능한 연결.
- **포트폴리오 연결**: 문제 구조, 분석 범위, 우선순위.

### 5. `hypothesis` — 가설 설정

- **자유 작성 안내**: 현상을 설명할 수 있는 원인을 복수로 쓰고 지지·기각 조건을 붙인다.
- **구조화 질문(5개)**:
  1. **[필수 후보]** 우선 영역을 설명하는 첫 번째 원인 가설은 무엇인가?
  2. **[필수 후보]** 경쟁하는 대안 가설은 무엇인가?
  3. 각 가설을 현재 지지하는 근거 또는 관찰은 무엇인가?
  4. 어떤 결과가 나오면 각 가설을 약화하거나 기각할 것인가?
  5. 먼저 검증할 가설과 이유는 무엇인가?
- **좋은 예시**: “H1: 상품명을 기억하지 못해 재탐색이 어렵다. H2: 기억하더라도 앱 검색 결과의 구분 단서가 부족하다. 검색어 회상률과 결과 식별 과정을 각각 확인한다.”
- **좋지 않은 예시**: “고객은 앱이 불편해서 구매하지 않는다.”
- **자주 하는 실수**: 가설 하나만 유지, 추상적 표현, 반증 조건 없이 지지 근거만 찾기.
- **placeholder**: “만약 [원인]이라면 [관찰 가능한 결과]가 나타날 것이다.”
- **도움말**: 서로 다른 증거로 구분할 수 없는 가설은 더 구체화한다.
- **최소 산출물**: 경쟁 가설 2개 이상, 각 가설의 검증·기각 단서.
- **완료 조건 후보**: 필수 후보 응답과 검증 가능한 표현.
- **포트폴리오 연결**: 가설, 선택 이유, 불확실성.

### 6. `evidence_validation` — 근거 수집·검증

- **자유 작성 안내**: 가설별 필요한 근거, 출처, 검증 방법, 현재 결과와 한계를 정리한다.
- **구조화 질문(5개)**:
  1. **[필수 후보]** 각 가설을 지지·기각할 증거는 무엇인가?
  2. **[필수 후보]** 근거의 출처, 시점, 수집 방법은 무엇인가?
  3. 어떤 작은 조사나 실험으로 확인할 수 있는가?
  4. 반대 증거나 대안 설명은 무엇인가?
  5. 현재 결론의 한계와 가설 상태는 무엇인가?
- **좋은 예시**: “검증 계획 예시로 5명의 탐색 과업을 설계할 수 있다. 이는 수행 결과가 아니라 방향 탐색용 계획이며 대표 표본이 아니다. 수행한다면 상품명 회상 실패와 결과 식별 실패를 별도 행동으로 기록한다.”
- **좋지 않은 예시**: “인터뷰에서 나왔으므로 H1이 증명됐다.”
- **자주 하는 실수**: 계획을 결과처럼 쓰기, 출처 누락, 지지 증거만 수집.
- **placeholder**: “주장–필요 근거–출처/방법–결과–한계를 연결해보세요.”
- **도움말**: 증거가 가설을 ‘증명’하기보다 어느 정도 업데이트하는지 표현한다.
- **최소 산출물**: 가설별 근거 또는 검증 계획, 출처, 한계.
- **완료 조건 후보**: 필수 후보 응답과 근거–가설 연결.
- **포트폴리오 연결**: 근거와 검증, 방법, 한계.

### 7. `decision` — 대안 비교·의사결정

- **자유 작성 안내**: 복수 대안, 비교 기준, trade-off와 재검토 조건을 적고 현재 결정을 내린다.
- **구조화 질문(5개)**:
  1. **[필수 후보]** 비교할 대안은 최소 두 개 이상 무엇인가?
  2. **[필수 후보]** 평가 기준과 그 기준이 중요한 이유는 무엇인가?
  3. 각 대안은 기준별로 어떤 근거와 불확실성을 가지는가?
  4. 무엇을 선택·보류하며 무엇을 포기하는가?
  5. 어떤 조건에서 결정을 재검토할 것인가?
- **좋은 예시**: “아직 검증 결과가 없으므로 매장 기록 단서 제공과 앱 검색 개선을 학습 속도·실행 비용·범위로 비교하고, 작은 과업 테스트가 가능한 기록 단서 prototype을 먼저 검토하는 잠정 결정을 둔다.”
- **좋지 않은 예시**: “QR이 가장 혁신적이므로 선택한다.”
- **자주 하는 실수**: 대안 하나, 선택 후 기준 만들기, 근거 없는 점수 정밀화.
- **placeholder**: “대안 / 기준 / 근거 / trade-off / 재검토 조건을 적어보세요.”
- **도움말**: 선택하지 않은 대안의 장점도 공정하게 기록한다.
- **최소 산출물**: 대안 2개 이상, 기준, 선택·보류 이유, 재검토 조건.
- **완료 조건 후보**: 필수 후보 응답과 검증 근거 참조.
- **포트폴리오 연결**: 대안 비교, 결정, trade-off.

### 8. `solution_execution` — 해결안 설계·실행

- **자유 작성 안내**: 선택한 대안을 가장 작게 검증할 실행 단위, 역할, 일정, 지표와 위험으로 바꾼다.
- **구조화 질문(5개)**:
  1. **[필수 후보]** 선택한 해결안의 범위와 제외 범위는 무엇인가?
  2. **[필수 후보]** 가장 작은 검증 행동과 기대 학습은 무엇인가?
  3. 누가 언제 무엇을 하며 의존성은 무엇인가?
  4. 성공·중단·확대 기준은 무엇인가?
  5. 주요 위험과 대응은 무엇인가?
- **좋은 예시**: “실행 설계 예시로 실서비스 출시 전 가상 상품 3개를 사용하는 기록 단서 prototype 과업을 계획하고, 수행 시 재탐색 성공 여부와 혼동 지점을 관찰한다. 이는 구현 또는 수행 결과가 아니다.”
- **좋지 않은 예시**: “전 매장에 기능을 출시하고 반응을 본다.”
- **자주 하는 실수**: 할 일만 나열, 검증 질문과 지표 누락, 범위 과대.
- **placeholder**: “작은 검증 행동–담당–시점–판단 기준–위험을 연결해보세요.”
- **도움말**: 실행의 목적은 기능 완료가 아니라 불확실성을 줄이는 학습일 수 있다.
- **최소 산출물**: 실행 단위, 담당·시점, 판단 기준, 위험.
- **완료 조건 후보**: 필수 후보 응답과 결정 단계의 추적 가능한 연결.
- **포트폴리오 연결**: 해결안과 실행, 역할, 위험 관리.

### 9. `result_evaluation` — 결과 평가

- **자유 작성 안내**: 실제 결과가 있으면 목표와 비교하고, 없으면 측정 계획을 결과처럼 꾸미지 말고 구분한다.
- **구조화 질문(5개)**:
  1. **[필수 후보]** 실제 관찰 결과인가, 아직 측정 계획인가?
  2. **[필수 후보]** 실행 전 판단 기준과 비교하면 무엇이 달라졌는가?
  3. 예상 밖 결과와 부작용은 무엇인가?
  4. 결과를 설명할 다른 원인과 측정 한계는 무엇인가?
  5. 유지·수정·중단 중 다음 판단은 무엇인가?
- **좋은 예시**: “아직 실행 전이므로 성과는 없다. prototype 검수에서는 과업 성공과 혼동 지점을 기록하고, 소표본 한계를 명시한다.”
- **좋지 않은 예시**: “이 기능은 구매 전환율을 크게 높일 것이다.”
- **자주 하는 실수**: 계획을 성과로 표현, 활동량을 결과로 대체, 실패·부작용 생략.
- **placeholder**: “결과/계획 구분–기준 비교–한계–다음 판단을 적어보세요.”
- **도움말**: 데이터가 없다는 사실도 중요한 결과 상태다.
- **최소 산출물**: 결과 상태, 기준 비교 또는 측정 계획, 한계, 다음 판단.
- **완료 조건 후보**: 필수 후보 응답과 과장 없는 상태 표시.
- **포트폴리오 연결**: 결과 평가, 한계, 다음 개선.

### 10. `conclusion_reflection` — 결론 전달·회고

- **자유 작성 안내**: 핵심 결론과 근거를 짧게 연결하고 최초 생각이 어떻게 바뀌었는지 회고한다.
- **구조화 질문(5개)**:
  1. **[필수 후보]** 지금 전달할 결론과 핵심 근거는 무엇인가?
  2. **[필수 후보]** 최초 생각과 최종 판단은 어떻게 달라졌고 무엇이 바꾸었는가?
  3. 남은 불확실성과 반대 의견은 무엇인가?
  4. 이번 Case에서 잘한 사고와 놓친 사고는 무엇인가?
  5. 다음 Case에 재사용할 원칙과 다음 행동은 무엇인가?
- **좋은 예시**: “처음에는 검색 기능 부족을 원인으로 보았지만, 문제를 기억과 식별 단계로 나눈 뒤 어느 지점이 큰지 먼저 검증해야 한다고 판단을 바꿨다.”
- **좋지 않은 예시**: “분석을 잘했고 좋은 해결책을 찾았다.”
- **자주 하는 실수**: 새 주장 추가, 불확실성 제거, 감상만 쓰기.
- **placeholder**: “결론–근거–변화–한계–재사용할 원칙 순서로 정리해보세요.”
- **도움말**: 최종 판단보다 생각을 바꾼 증거와 이유가 성장 기록의 핵심이다.
- **최소 산출물**: 결론, 근거, 최초·최종 비교, 한계, 재사용 원칙.
- **완료 조건 후보**: 필수 후보 응답과 앞 단계 원본 참조.
- **포트폴리오 연결**: 결론, 회고, 역량, 다음 개선.

## 4. Open Decision

- 질문 수를 모든 Case 유형에 고정할지 템플릿별로 바꿀지
- 필수 질문 1~2개의 정확한 선택과 미응답 처리
- 긴 텍스트 외 선택, 체크박스, 출처 입력 같은 field type
- 예시를 작성 전부터 보여줄지 요청 시 펼쳐볼지
- 완료를 사용자 확인으로 할지 후보 조건 충족과 결합할지
- Case 난이도에 따라 도움말과 구조화 정도를 어떻게 줄일지
