# Thinking Flow V2 Practice Case System

## 1. 목적

Practice Case는 정답을 제공하는 문제가 아니라 10단계 사고 절차를 반복 연습할 맥락과 제약을 제공한다. Case 정보는 관찰 사실, 제공된 전제, 검증이 필요한 가정을 명확히 구분해야 한다.

## 2. Case 유형 후보

| 유형 | 학습 초점 | 예시 |
| --- | --- | --- |
| 서비스 문제 | 사용자 여정과 서비스 의사결정 | O2O 탐색 여정 |
| 데이터 분석 문제 | 질문 정의, metric, 근거 한계 | 전환 하락 원인 탐색 |
| 업무 개선 문제 | 프로세스와 운영 trade-off | 반복 업무 개선 |
| 프로젝트 회고 | 결과 평가와 학습 | 팀 프로젝트 회고 |
| 기업 Case | 공개 정보 기반 현업형 문제 | 공개 자료 기반 가상 Case |
| 자유 주제 | 사용자가 자신의 문제 입력 | 개인 프로젝트 결정 |
| 면접 Case | 시간 제한 구조화와 전달 | 직무 Case 질문 |
| 일상 문제 | 낮은 진입 장벽의 반복 훈련 | 학습 계획 선택 |

## 3. 난이도 후보

- **입문**: 범위가 좁고 알려진 전제·예시·추천 프레임워크가 충분하다.
- **기본**: 일부 정보 공백이 있고 사용자가 가설과 검증 계획을 만든다.
- **심화**: 이해관계자와 trade-off가 복수이며 불완전한 근거를 다룬다.
- **도전**: 문제 정의 자체가 열려 있고 프레임워크 선택도 사용자 몫이다.

난이도 판정 규칙은 Open Decision이다.

## 4. Case metadata 후보

| 필드 | 의미 | 상태 |
| --- | --- | --- |
| `title` | Case 제목 | 현재 개념 재사용 |
| `summary` | 짧은 문제 상황 | 현재 개념 재사용 |
| `businessRequest` | 사용자가 도울 업무 요청 | V2 후보 |
| `knownPremises[]` | Case가 제공하는 알려진 전제와 출처 상태 | V2 후보 |
| `informationToValidate[]` | 검증이 필요한 정보 | V2 후보 |
| `caseType` | 서비스·데이터·회고 등 분류 | V2 후보 |
| `difficulty` | 입문·기본·심화·도전 | V2 후보 |
| `recommendedFor[]` | 추천 사용자·직무 | V2 후보 |
| `frameworkIds[]` | 사용 가능한 프레임워크 | V2 후보 |
| `expectedOutputs[]` | 기대하는 산출물 유형 | V2 후보 |
| `portfolioEligible` | 포트폴리오 변환 가능 후보 | V2 후보 |
| `sourcePolicy` | 공개 정보·가상 설정·사용자 제공 구분 | V2 후보 |

정확한 타입과 필수 여부는 `09_V2_DATA_MODEL.md`에서 확정 전 후보로 관리한다.

## 5. Case 상세 화면

Case 시작 전에는 다음을 보여준다.

- 제목, 한 줄 요약, 유형과 난이도
- 문제 상황과 업무 요청
- 알려진 전제와 “사실/가상 설정/가정” 배지
- 검증이 필요한 정보
- 추천 대상과 예상 학습 시간 후보
- 사용할 수 있는 프레임워크(정답 경로로 강제하지 않음)
- 예상 산출물과 포트폴리오 전환 가능성

Case 시작 전 `initialImpression`, `initialSolutionIdea`, `decisionQuestion`을 받지 않는다. 첫 생각과 목적은 `context`, 문제 질문은 `problem_definition`, 해결안은 `solution_execution`에서 다룬다.

## 6. 유형별 정책

### 자유 주제 Case

사용자가 제목과 맥락을 제공하되, `context` 단계의 사고를 대신 완성시키는 과도한 사전 양식은 피한다. 안전·개인정보 안내와 빈 Case 시작에 필요한 최소 필드는 Open Decision이다.

### 기업 Case

- 공개 출처와 가상 설정을 구분한다.
- 내부 행동·성과 수치를 검증된 사실처럼 만들지 않는다.
- 특정 기업의 공식 과제로 오해할 표현을 피한다.
- 오래된 공개 자료에는 기준 시점을 표시한다.

### 포트폴리오 전환 가능 Case

공개 가능한 출처, 사용자의 역할, 결과 상태, 민감 정보 여부를 확인할 수 있어야 한다. `portfolioEligible`은 자동 공개 허가를 뜻하지 않는다.

## 7. Seed data 기준

- 각 문장은 제공 사실, 공개 출처, 가상 설정, 사용자 검증 필요 중 하나로 분류 가능해야 한다.
- 해결안을 문제 문장에 숨기지 않는다.
- 최소 두 가지 이상의 합리적 접근이 가능해야 한다.
- 10단계 모두에서 사고할 충분한 맥락이 있으나 정답은 제공하지 않는다.
- 좋은 예시는 Case seed와 분리하여 학습 콘텐츠로 관리한다.
- fixture는 Zod로 검증하고 Stage key를 하드코딩해 중복 관리하지 않는다.

## 8. Practice Library

V2 후보:

- 유형, 난이도, 추천 직무, 예상 시간, 포트폴리오 가능 여부 필터
- 제목·상황·학습 목표 검색
- 시작하지 않은 Case, 진행 중 Case, 완료 Case 구분
- Case 카드에서 사실 범위와 난이도를 짧게 확인
- 정렬: 추천, 최근 추가, 난이도, 예상 시간

개인화 추천과 검색 ranking은 초기 V2 구현 범위로 확정하지 않는다.

## 9. Open Decision

- Case 시작에 정말 필요한 최소 metadata
- 난이도와 예상 시간 계산 방식
- 자유 주제에서 민감 정보 감지·안내 범위
- 기업 Case의 출처 갱신 책임과 검수 주기
- 한 Case가 여러 템플릿 버전을 사용할 때 고정·업데이트 정책
- Library 검색과 개인화 추천의 첫 구현 범위
