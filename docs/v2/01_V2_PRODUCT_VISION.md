# Thinking Flow V2 Product Vision

## 1. 해결하려는 사용자 문제

AI를 자주 활용하는 취업준비생과 직무 전환자는 빠르게 그럴듯한 결과를 얻을 수 있지만, 문제를 관찰하고 구조화하며 근거로 판단하는 자신의 사고 절차를 반복 훈련하고 증명하기 어렵다. 결과물만 남으면 무엇을 어떻게 바꾸었는지, 다음 문제에 재사용할 수 있는 원칙이 무엇인지도 사라진다.

## 2. 근본 문제

- 빈 화면에서는 생각을 시작하기 어렵고, 완성된 AI 답안을 보면 자신의 사고가 쉽게 대체된다.
- 사고법 설명, 실제 작성, 피드백, 수정 이력이 여러 도구에 흩어진다.
- 최종 결과 중심 포트폴리오는 판단 과정과 역량의 근거를 보여주기 어렵다.
- 반복 훈련의 성장과 취약점을 확인할 데이터 구조가 없다.

## 3. 목표 사용자

대표 사용자는 AI를 활용하면서도 논리적 사고력과 문제 해결력을 스스로 키우고 프로젝트·포트폴리오로 증명하려는 취업준비생과 직무 전환자다. 이후 확장 후보는 실무 초년생, 교육 프로그램 참여자, 면접 Case를 준비하는 사용자다.

## 4. 사용 전과 사용 후

| 사용 전 | 사용 후 |
| --- | --- |
| AI에게 바로 답을 요청한다. | 자신의 초안을 먼저 작성하고 필요한 점검만 요청한다. |
| 문제, 가설, 대안이 한 문장에 섞인다. | 10단계에서 사고 요소와 산출물을 구분한다. |
| 수정 전 생각이 사라진다. | 최초 초안과 수정 이유가 연결되어 남는다. |
| Case가 끝나면 결과만 남는다. | 분석과 포트폴리오가 원본 사고 기록을 참조한다. |
| 성장 여부를 감으로 판단한다. | 여러 Case의 패턴과 변화를 후보 metric으로 확인한다. |

## 5. 핵심 가치

1. **사고 주도권**: 답을 받기 전에 사용자가 먼저 생각한다.
2. **절차 학습**: 10단계를 반복하며 문제 해결 절차를 내재화한다.
3. **변화의 증거**: 초안, 근거, 피드백과 수정 이력을 보존한다.
4. **전환 가능한 기록**: 사고 데이터가 분석과 포트폴리오의 근거가 된다.
5. **설명 가능한 판단**: 선택뿐 아니라 대안, 기준, 불확실성을 남긴다.

## 6. 제품 원칙

- 사용자 선작성과 AI 후개입
- 사실·해석·가설·근거 구분
- 자유 작성과 구조화 입력의 전환 가능성 및 양쪽 데이터 보존
- append-only 버전 이력
- 미완료 이동을 막지 않는 Soft Gate
- AI가 단계 완료나 최종 대안을 대신 결정하지 않음
- Practice Case의 미검증 내용은 사실이 아니라 가정·가설로 표시
- 파생 결과물에서 원본 사고 기록으로 역추적 가능
- 사용자의 데이터 소유권과 내보내기 가능성을 설계 기준으로 검토

## 7. 비목표

- 한 번의 요청으로 완성 답안을 생성하는 서비스
- AI가 사용자를 대신해 모든 단계를 자동 완성하는 기능
- 검증되지 않은 기업 내부 데이터나 성과를 사실처럼 제시하는 Case
- V2 첫 구현에서 실제 LLM, RAG, 고급 통계 분석, 협업·로그인을 동시에 제공하는 것
- 포트폴리오 문장을 원본과 분리된 최종 텍스트로만 저장하는 것

## 8. 성공 지표 후보

아래는 설계 후보이며 목표값과 계산식은 확정되지 않았다.

- 첫 Case에서 `context` 초안을 작성한 사용자 비율
- 시작한 Case 중 10단계까지 도달한 비율
- 사용자가 AI 점검 전에 먼저 작성한 비율
- Case별 의미 있는 수정과 checkpoint 수
- 근거·출처가 연결된 판단 비율
- 두 번째 Case를 시작한 사용자 비율과 단계별 소요 시간 변화
- 포트폴리오 변환 후 원본 기록을 다시 검토한 비율
- 사용자 자기평가에서 사고 절차 인지와 설명 가능성 변화

metric 정의와 개인정보 원칙은 `05_V2_THINKING_DATA_SYSTEM.md`에서 다룬다.

## 9. 제품 경계

V2 설계는 Thinking Learning, Thinking Data, Thinking Portfolio를 하나의 흐름으로 연결한다. 그러나 구현은 `10_V2_DEVELOPMENT_ROADMAP.md`의 vertical slice로 나눈다. 설계에 포함됐다는 이유만으로 모든 기능이 현재 구현되었거나 첫 배포 범위라는 뜻은 아니다.

## 10. Open Decision

- 대표 사용자를 취업준비생·직무 전환자에 얼마나 오래 집중할지
- 첫 성공 순간을 “첫 단계 저장”, “Case 완료”, “포트폴리오 생성” 중 무엇으로 정의할지
- 성장 metric을 사용자에게 언제, 어떤 설명과 함께 노출할지
- 교육용 예시의 업종·직무 범위와 난이도 체계
- 공개 포트폴리오 기능의 MVP 포함 여부
